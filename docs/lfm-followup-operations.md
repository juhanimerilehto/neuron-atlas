# LFM depth: durable execution and publication

Run commands from the Neuron Atlas repository root. The finite programme directory is `campaigns/lfm-depth-20261127-v1`. `programme.json` records the authorized stages, cumulative ceilings and recovery policy. Each `stages/<id>` retains its immutable manifest, exact prompt plan, native preflight, per-checkpoint SQLite journal, response pairs, accepted reviews, independent audit and append-only `events.jsonl`.

The first study is `stages/01-confirm-p9`. Its source is `lfmfollow/confirmation_v1.py`; its shared foundation is `core_v1.py`. Do not modify these frozen numerical sources after jobs begin. Use a separately versioned recovery with a documented reason if a correction is required.

## Start and inspect

The existing `.venv-qwen` interpreter enters the isolated native runtime through `scripts/run_lfm_followup.py`. First run `preflight_v1`, then `freeze_v1`. Publish the frozen plan and verify it before writing the first stage's `preregistration-receipt.json`. The receipt binds the manifest identity and verified commit. `confirmation_v1` refuses to create measured jobs without that receipt.

`scripts/launch_lfm_followup.py confirmation_v1` detaches the first finite worker. `.cache/lfm-followup-service.json` records its PID and log. Verify that PID outside the restricted sandbox process view before recovery; a sandboxed process lookup can falsely report a detached worker missing. A duplicate live process is rejected. Preserve unrelated GPU workloads.

Read real counts from the stage's `<checkpoint>/jobs.sqlite` using SQLite `mode=ro`. Status files update after prompt batches, so journal counts can be ahead. Cumulative budgets include all stage journals and all requests under the programme's shared `codex` and `codex-confirm` directories. Never reset those directories or attempt counters.

After the first audit, `scripts/launch_lfm_followup.py programme_v1` runs the remaining finite sequence. Programme state is `campaigns/lfm-depth-20261127-v1/status.json`; its `events.jsonl` is append-only. Per-process logs are under the programme's `logs/` folder and the detached service log recorded in `.cache/lfm-followup-service.json`. The queue retries a failed stage process at most three times without resetting numerical jobs or reviewer attempts. Pending reviewed publications are recorded in `pending-publications.json`. After measurement and export it waits up to twelve hours for verified stage receipts, then exits resumably if publication is still pending.

The timing prototype's first full-prefix replay check failed before any timing-stage jobs. That failure is retained in `diagnostics/timing-preflight-v1-failure.json`. The separately versioned `preflight_timing_v2` requires exact agreement with an independently coded cached manual hook, while retaining full-prefix BF16 drift as a diagnostic. Timing and pair jobs cannot start before the versioned preflight passes; this change does not alter the first confirmation's worker or evidence.

Before stages 04/05 froze or wrote jobs, the post hoc weight comparison motivated the saved `adaptive-design-late-region-v1.json`. Those stages reserve two candidate coordinates from layers with edited W2 matrices, and the pair study reserves their joint pair. Previous builder sources remain in `diagnostics/pre-late-region-design/`; revised hashes and verification are in the amendment. Their manifests will bind the geometry, amendment and parent-validation references through `protocol.external_input_sha256`. The independent integrity checker verifies those inputs as well as source files. Six timing coordinates, eight pair-pool coordinates and sixteen pairs preserve the prior budget maxima.

## Recovery and publication

Run `.venv-qwen/Scripts/python.exe scripts/lfm_followup_status.py --compact` for a read-only summary of stage audits, real completed journal counts, cumulative reviewer requests and publication receipts. It uses only the standard library and does not load model weights.

Run `scripts/audit_lfm_followup.py --partial --require-publication` with that interpreter to independently check completed-stage jobs, source hashes, prompt partitions, catalogue totals and saved publication receipts while later work is running. Random controls intentionally reuse the first eight held-out prompts; discovery, validation and held-out partitions are disjoint. At completion omit `--partial`, add `--verify-weights`, and save the result with `--output campaigns/lfm-depth-20261127-v1/final-integrity-check.json`. This checker uses read-only SQLite connections and does not invoke a model or reviewer. It complements the worker's raw review replay and the publisher's deployed-byte checks.

Read the log, manifest, current status and raw failures first. Restart the same frozen entry point to reuse completed jobs and accepted reviews. Process recovery is bounded; persistent source or reviewer errors require an explicit versioned diagnosis. Preserve incomplete evidence instead of fabricating an assessment. A passed numerical audit does not turn failed semantic criteria into a positive finding.

After a stage audit, export new observations with unique programme/stage IDs; preserve all older records, even for the same coordinate. Prepare the static release with `scripts/prepare_public_update.py`, run the release's `node scripts/check_public_snapshot.mjs`, inspect the actual remote main head, require expected blob/tree hashes and update the branch without force using an expected-head lease. Verify Pages with `scripts/verify_public_deployment.py` and retain the publication receipt. Pending changes and uncertain mutations belong in the publication outbox; inspect the remote head before retrying a ref update.

For stages04/05, first run `scripts/check_lfm_timing_exposure_v1.py <stage-id>`. This post hoc integrity check validates saved schedules and exact generated-token equality before the first recorded intervention, including identical outputs when there was no exposure. It records any failure before refusing publication. The public exporter and independent checker require a passed result. This supplements native preflight; it does not change behavioral gates. Accepted-condition downloads additionally retain recorded exposure counts, with all assigned cases kept in their original denominator. Preserve any failed check for versioned diagnosis rather than editing evidence.

After that verification, run `scripts/record_lfm_stage_publication.py <stage-id>` with the campaign interpreter for stages 02–05. It checks that the verified immutable release contains the current audit, outcomes, polished report and catalogue verdicts, writes completion metadata, archives the publication outbox, then atomically writes the receipt read by the finite queue. Do not rerun the report-generating publisher over manually polished reports without first preserving them.

Optionally run `scripts/compare_lfm_followup.py <stage-id>` after a completed stage. It saves a post hoc, prompt-matched comparison of reviewer flags without issuing a new request or changing a gate. Common-target match comparisons are meaningful only where the frozen checkpoint descriptions are identical; the output marks this explicitly. These comparisons are descriptive and do not establish that abliteration caused a difference or that the underlying mechanisms are equivalent.

Run `scripts/diagnose_lfm_reviews_v1.py <stage-id>` to summarize saved rejected attempts. It replays schema and evidence-reference checks without making requests, repairing responses or accepting them. The timestamped `review-diagnostics-latest.json` distinguishes a recovered bounded retry from an unavailable review group; raw attempts remain local. Refresh this diagnosis after a stage finishes, then include it in the public snapshot. An unavailable review is neither a negative behavioral result nor a passed condition.

Optional saved-output supplements `scripts/lfm_token_prefix_v1.py <stage-id>` and `scripts/lfm_repetition_diagnostics_v1.py <stage-id>` make no model calls and never change verdicts. They bind source and input hashes; the integrity checker verifies these. Preserve existing versioned outputs and sources, using another version for any correction. Literal repeated tokens are not a semantic collapse classifier; see [the repetition note](lfm-repetition-diagnostics.md).

The numerical worker does not have independent GitHub credentials. A connected publisher handles public deployment; a future session can resume from these files. Later locally frozen exploratory stages may finish and queue reviewed exports while publication is unavailable. Their public reports must distinguish local freezing from the first study's public preregistration.

The pair study was also frozen in advance through the metadata-only `freeze_pairs_v1` helper while stage04 was still running. It calls the same preflight, builder and freeze functions as the normal entry point, with exactly the same numerical sources; it constructs no worker, journal or reviewer. Preserve `premeasurement-registration.json` and the eventual verified `preregistration-receipt.json`. Confirm the deployed manifest bytes, zero pair jobs and the queue still on stage04 before recording that receipt. The normal finite queue remains responsible for pair measurements; do not launch a second worker.
